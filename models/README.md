# 候选模型台账

**这里记的是「我们可能在产品里用到的模型」—— 不是出货的东西。** 每条一个文件，文件名即 slug。

## 与既有三层的分工（不要往这里塞它们的内容）

| 层 | 在哪 | 管什么 |
|---|---|---|
| **出货的引擎** | `build/providers.config.js` · `build/stt.config.js` · `build/tts.config.js` · `build/model-params.config.js` | **已经出货**的引擎 / 端点 / 模型参数，按**请求格式**分族（不按厂商），有门禁；运行时只读生成的 `*.gen.js` |
| **实测与推荐（翻译族）** | `build/recommend.config.js` + `build/perf-ledger.config.js` | 测过的**翻译**模型该选哪个（生成 `docs/model-recommendations.md`，不要手改那份） |
| **候选（本目录）** | `models/*.md` | **还没出货、我们在看**的模型：事实、许可、硬件下限、我们要不要把时间花在它身上、以及**我们为什么暂时不选它** |

**本目录不参与构建、不被运行时读**：它是台账，不是注册表。把一条候选**晋升**到出货，是
`docs/domain-design.md` 意义上的领域设计变更 —— 改哪个 config、要不要先过条款，写在每条自己的
「治理」一行里。

## 状态图例

| 状态 | 意思 |
|---|---|
| `candidate` | 刚记进来，只有事实 |
| `spike` | 决定花一点时间实测（spike 的内容与判据写在「结论」里） |
| `watch` | **我们不打算动手，在等一个触发条件**（条件写在「结论」里）—— 与 `parked` 的区别：`parked` 是我们自己判断眼下不值，`watch` 是**外部/上游条件还没到**（等某条裁定、等姊妹条的实测结论） |
| `adopted` | 已进出货注册表（**这时该条只留「当时的判断」，权威在 config 里**） |
| `parked` | 方向对，但眼下不值/没条件（写清什么时候再看） |
| `rejected` | 明确不用 —— **也要留档**，否则半年后有人会重新提一遍 |

## 入选判据（按顺序问，前两条是否决项）

1. **能不能不依赖我们的服务端**：端上跑，或**用户自己托管**。（`AGENTS.md` 规则 2：免费路径永远不依赖我们的服务端。）
2. **许可能不能自托管 / 随包分发**：Apache / MIT / OFL 一类 ✓；专有或「研究限定」要单独写清代价。
3. **硬件下限**对我们四个面（iPhone / iPad / Mac / 移植后的 Android）意味着什么 —— 端上跑不动就写「只能自托管」。
4. **中 / 英覆盖**：我们主力语对。别为长尾语种引入一条新的基础设施。
5. **实测数字必须是我们自己的**：数据集 + 指标 + 日期。**没测就写「我们没测过」**，厂商宣称照抄但要标明「未经我们复核」。
6. **晋升路径**：进哪个 config、要不要先过 `domain-design` 的哪一条。

## 每条必须有的字段（`test/models-index.test.js` 会拦）

`来源` · `任务` · `许可` · `形态` · `跑在哪` · `服务的面` · `实测` · `结论` · `治理`

写法是 `**字段**：值`（值不能为空）。字段固定下来是为了**晋升那天可以逐字搬进 config**，
而不是每次重新组织一遍。加字段可以，删字段要连带改门禁。
