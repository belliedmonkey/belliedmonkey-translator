# growth-spec —— 运营面的规约

面向用户的**非产品面**（社区、README、官网文案、商店文案、对外发的每一句话）归这里管。
产品内的交互与文案在 [`docs/interaction-spec.md`](interaction-spec.md)，SEO/GEO 的确定性
检查在 [`docs/seo-geo-checklist.md`](seo-geo-checklist.md)，遥测口径在
[`docs/telemetry-design.md`](telemetry-design.md)。**这份只写那些「靠人记着就会破」的规则**，
每条都带它是被什么事件逼出来的。

---

## 1. 每个面说什么语言

**社区面一面一语，不混。**

| 面 | 语言 | 备注 |
|---|---|---|
| **Discord** | **只用英文** | 频道名、频道主题、置顶、公告、**以及我们自己的每一条回复**。用户用别的语言发言不拦、也照常回 —— 但**回的是英文** |
| 中国版的微信 / QQ 群 | 只用中文 | 同一条规则的另一半 |
| `belliedmonkey.cc` | 12 语种 i18n | 预渲染，见 seo-geo-checklist |
| `belliedmonkey.com` | 只用中文 | 不做 i18n，`AGENTS.md`：非必要勿增实体 |
| `README.md` / `README.zh-CN.md` | 各自一种，互不混 | |
| GitHub Issues / Discussions | **跟提问者的语言走** | 那是别人开的帖，不是我们的场子 |
| 商店文案 | 按 locale | |

**为什么 Discord 只用英文**（2026-09-20 用户裁定）：

- 量在英文那边。85% 的下载来自 Apple 自然搜索，覆盖 36 个国家（见
  [[oss-marketing-direction]] 的口径）。
- **双语房间对两边都更差**：英文读者每翻一屏只有一半能读，会觉得自己是客人；中文读者
  则会默认这里说中文，于是英文提问没人接。一间房只能有一种默认语言。
- 中文用户**不靠 Discord 服务**：Discord 在中国大陆打不开，中国版的入口本来就指向别处
  （现为 GitHub Discussions，微信群建好后换掉，见 `extension/learn/feedback.js`）。
  所以「照顾中文用户」不是留在 Discord 里说中文的理由 —— 真正需要照顾的那批人根本进不来。

**不是规则的部分**：用户在 Discord 里用什么语言发言，随他。产品自己就是翻译器，
读懂不是问题。规则约束的只有**我们发出去的字**。

## 2. 开一个新社区面之前，先证明它养得活

2026-09-06 给「开实时群」立过门槛，2026-09-20 兑现。**这个形状要保留**：
新面（论坛、微信群、Telegram、Reddit……）都先写下**可证伪的开设条件**，再照着对账。

那一次的两条分支与实测：

| 分支 | 实测（2026-09-20） |
|---|---|
| Discussions 累计 ≥ 20 个参与者 | **≈ 0** —— 唯一的帖子 15 天 0 回复 |
| `bt_daily` 连续 4 周周活 ≥ 50 | 09-07 周 **173**、09-14 周 **230**（门槛的 3.5–4.6 倍） |

第二条**只差时长不差人数**：遥测 2026-09-05 才开始收，「连续 4 周」物理上凑不齐。
门槛要挡的是「人还不够就开实时群」，230 周活已远远越过那个意思 —— 所以按**本意**
判定成立，而不是抠字面。**这类判断要写进提交信息，别只留结论。**

配套的规模判断：近 28 天真正用到核心功能的是 **85 人**。频道就开三个
（`#general` / `#help` / `#announcements`），不按语言分房 —— 这个规模再切一刀，
每间都显得没人。

## 3. 对外发的地址，发我们自己域名下的

**永远不要把第三方的短码直接写进产品或 README。** 发
`https://belliedmonkey.cc/<name>`，在 `belliedmonkey-cc/vercel.json` 里做 **307** 跳转。

- 产品里的地址会被**烤进 App Store 的二进制**，改不动；而第三方码会过期、会被换。
  实例：Discord 的「设置此链接为永不过期」在 2026-09 的客户端上**是坏的** —— 界面显示
  「永不过期」，API 回读 `expires_at` 仍是 30 天后，五条路都试过。
- 换目标只要改 `vercel.json` 一行 + 部署，**不用重新发版过审**。
- 顺带能量到点击（官网 2026-09-20 起有 Vercel Web Analytics）。
- **用 307 不用 308**：308 会被浏览器永久缓存，而这类目标一定会换。

产品里「社区在哪儿」的唯一登记处是 `extension/learn/feedback.js` 的
`COMMUNITY_URL_GLOBAL` / `COMMUNITY_URL_CHINA`。改这一处，四个面
（popup / 设置页 / 引导页 / 宿主 App）的「讨论」按钮一起跟着走。

## 4. 不能说一句那一版还不成立的话

**对外文案与它描述的功能必须同版上线。** 这条在产品侧已经有机械门禁兜着
（`build.js` 的 Gate B / F / G / H / I / J-1 / J-2），运营侧靠人 —— 而
2026-09-20 一天里就破了两次：

- **官网说了假话**：09-20 改准了 12 个语种隐私页的「no third-party analytics」，
  但**漏了 `llms.txt`** —— 它不在 i18n 字典里、每次要单独改。于是官网自己在跑
  Vercel Analytics，而站上给语言模型看的那份说明仍写着无限定的「没有第三方统计」，
  并且**已经上线**。（改站点文案的完整清单见 seo-geo-checklist；`llms.txt` 与
  预渲染语言页是两个最常漏的。）
- **差点提前发**：iOS「系统翻译」的隐私段一度要随站点先上线，而功能还在未合的 PR 里、
  Apple 一个包都没传。那会让隐私页用 12 个语种叫人去点系统菜单里根本没有的条目。
  拦下来的理由与 Gate J 当初拆成 J-1 / J-2 的理由是同一条。

**判据一律是回读线上，不是看本地文件、更不是看界面说了什么。**
改完站点文案，至少回读：目标那句、`llms.txt`、以及抽两个预渲染语言页。

## 5. 界面说「成功」不算成功

运营面上大量操作发生在别人的后台（Discord、商店、统计平台），而**它们的界面会撒谎**。
今天的三个实例：

- Discord 的「永不过期」：勾上了、文字也变了，API 与它自己的邀请列表都说还是 30 天。
- Vercel Web Analytics：脚本 200、页面上有 tag，**上报一条都没发** —— 脚本第一行是
  `if (navigator.webdriver || UA.includes('Headless')) return`，无头门禁永远验不到这一段。
- ASC 的媒体上传超限被错报成 500（见 [[asc-media-upload-500-and-delete-order]]）。

⇒ **每个动作都要有一条独立于该界面的判据**：API 回读、`curl -sI` 看状态码与 Location、
或换一个视图看同一份数据。拿不到独立判据的动作，宁可标成「未完成」。

## 6. 商店页（ASO）：每一版过一遍台账，每一次改动都要有前后对照

**为什么这一节存在**：App Store 曝光 ~99% 来自商店内搜索、外部引荐为 0（2026-09-21 与 09-25 两次读 ASC 分析报表），
所以**商店页就是唯一的获客面**。而在 2026-09-25 之前，关键词与副标题自 09-15 冻结后**一次都没测过效果**；
第一次测就发现副标题的前两个词 `live subtitles` 在美国店排 200 名外、第一个关键词 `interpreter` 也在 200 名外。

**单一来源与派生**：`store-assets/aso.md` 是两个平台共用的底稿，**不直接上传**；`scripts/gen-aso-platforms.js`
从它派生 `aso-ios.md`（多「系统翻译（iPhone）」一节）与 `aso-mac.md`（多「快速翻译（Mac App）」一节）。
一个平台的商店页上不写它没有的功能（Gate J-1 / J-2）。

**规矩**

1. **每一版、每个语种组只改一个变量。** 同时改关键词和副标题，结果出来就分不清是谁的功劳。
2. **关键词改完至少锁两个版本。** 发版节奏快，7–14 天的观察窗会被下一版覆盖 —— 不锁住，台账里每一条都说不清
   是哪一次改动起的作用。
3. **成败看搜索曝光与下载，不看名次。** 名次（`npm run aso:rank`）来自 iTunes Search API，不是商店 App 的个性化排序、
   只给前 200，**只当趋势**：取多次快照中位数、只认跨档（200+ → 前 100 → 前 50 → 前 10）。判据是
   `npm run asc:sources`（各地区来自搜索的曝光）与 `node scripts/asc.js installs`（各国下载）。
4. **Apple 的搜索只索引名称、副标题、关键词字段**，不索引描述。所以改描述影响的是转化，不是排名 ——
   别在台账里把描述改动当排名实验记。`promotionalText` 随时可改（`asc.js aso … --promo-only`）、不影响排名，
   适合当不用发版的转化实验。
5. **竞品名永不进关键词**（`aso.md` 四条约束、`test/lib/copy-redlines.js`）。官网 / README 可以写。
6. **每一条改动都进台账** `store-assets/aso-ledger.md`：平台 · 语种 · 字段 · 改前 / 改后原文 · 假设 · 基线读数 ·
   过审后 7 天与 14 天的读数 · 结论（adopted / rejected / inconclusive）。「测过且否定」与「没测过」是两件事 ——
   和 `build/perf-ledger.config.js` 同一个道理。
7. **零评分下头部词排不上。** 评分是排序的权重项；在评分起来之前，关键词优先放**能排进前 50 的长尾 / 组合词**，
   先用 `aso:rank` 测候选词当前名次再选（候选词放进 `store-assets/aso-keywords.json`，让它们先攒几天）。

**什么时候做**：发版流程 `/store-release` 第 6.5 步 —— 版本记录建好、还没提审的那段时间，是唯一能改的窗口。
付费 ASO 工具（真实名次、关键词热度）等免费数据跑满 2–4 周之后再评估。
