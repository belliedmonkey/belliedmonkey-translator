# 实时形态端到端协议

两条分开记。不合成一个分数。质量、延迟、成本 **待测**。样本数为 0，见 [samples.md](../samples.md)。

## realtime-listen

适用范围：App 首页「对话 · 实时听译」，`listenModel.open` 不带 `'subtitle'`。版本见清点的 `sourceVersion`。

用户可见维度：

- 首结果时延：半句临时译文或第一行定稿，取先出现的那个，并写明是哪一个
- 稳定结果时延：该句不再被后续修订替换
- 连续性：正式 final 是否都出现在出行文字里
- 修订抖动：同一句上屏后再改的次数

字幕同步：对话主界面不是播放器字幕。除非同一次运行真的把结果画进字幕条，否则这一维记 `not-applicable`，不填数字。

输入：麦克风 PCM。输出：每行原文与译文；默认可以朗读。

阶段切片用清点矩阵里 `realtime-listen` 那一行。归因至少分开：听写臂（`sa` / `e1_b1` / 可选泰语 Grok）、断句路由（`model` / `legacy`）、修正是否被 `acceptCorrection` 收下、译文、朗读开始时刻。`listen-core.js` 的 `latencySummary` 已能汇总 `lat.pass` 与 `lat.ttsStart`，那是代码里的口径，不是已采集的基线。

阻塞：没有授权音频与转写对照。不能用测试里的回放字符串当真实失败集。

## realtime-subtitles

适用范围：App 首页「实时字幕」，`open('subtitle')`。与听译共用桥，断句不走模型路由器。

用户可见维度：

- 首结果时延、稳定结果时延、连续性、修订抖动：定义同上
- 字幕同步：上屏文本相对正在播放的声音的偏移。系统声或麦克风要在记录里写明（`captureSource`）

输入：设备正在播放的声音。输出：双语字幕行。不自动朗读。

阶段切片用矩阵的 `realtime-subtitles` 行。修正走 T/X，不走模型断句 JSON。不要把对话模型断句的分数抄到这里。

阻塞与听译相同：没有授权的播放声与对照稿。Mac 本地文件离线转写不在本协议里。
