# B2c：翻译阶段可复现性——seed 不可用，噪声在译文不在评委

时间：2026-11-18 11:00–11:15 CST。授权：用户同意「查翻译阶段的种子/采样可控性」。
结论：**`seed` 被接口接受（HTTP 200）但不被遵守**；同一输入、同一参数、`temperature=0` 下 6 次重复仍产生 2–5 种输出。评委在**条目级**稳定（12/12 个 item×judge 单元，4 次重复零翻转），纠纷来自译文在评委判定边界上的摆动。所以协议不能靠 seed，只能靠**重复采样 + 报通过率**。

这不是产品分、不是验收。样本 6 条，只够定位噪声源和定协议。

## 1. seed 不可控

固定：同一系统提示词（sha `75e06b87…`）、同一模型 `qwen3.7-plus`、同一端点、产品 `enable_thinking:false` 片段。变量只有 `temperature` 和 `seed`。

| 条件 | 每 item 调用 | 不同输出数（6 条 item） |
|---|---|---|
| `temperature=0`，无 seed | 6 | 1, 1, 2, 3, 3, 4 |
| `temperature=0`，`seed=42` | 6 | 1, 2, 2, 4, 5, 2 |
| `temperature=0`，`seed=7` | 4 | 1, 2, 2, 3, 4, 2 |
| `temperature=1`，无 seed | 4 | 1, 3, 3, 4, 4, 4 |

- 全部 120 次调用 HTTP 200，`seed` 字段没有引发 400，说明**被接受**。
- 回包里**没有 `system_fingerprint`**，无法从响应判断是否生效；重复实验说明**没有生效**：`seed=42` 的 6 次里最多出现 5 种不同输出。
- 差异量级：`temperature=0` 下相对编辑距离中位数约 5–13%，最大 42.9%（`ascend/00004`：`I am so` ↔ `I so`，语义级）；`temperature=1` 最大 65%。

同一条 item 在 `seed=42` 与 `seed=7` 下也不相同，说明不是“固定种子但种子值不同”，而是采样本身不受控。

## 2. 评委稳定在条目级

同一份冻结译文、同一提示词（sha `2fa67bbe…`），每个评委判 4 次，6 条 item：

| item | judge-a 过/败 | judge-b 过/败 | 维度失败集合种类 |
|---|---|---|---|
| 1671（双过） | 4 / 0 | 4 / 0 | 1 / 1 |
| en_us/1672（双过） | 4 / 0 | 4 / 0 | 1 / 1 |
| ascend/00055（双过） | 4 / 0 | 4 / 0 | 1 / 1 |
| en_us/1680（双败） | 0 / 4 | 0 / 4 | 2 / 1 |
| ascend/00028（双败） | 0 / 4 | 0 / 4 | **4** / 1 |
| cmn/1668（分歧） | 4 / 0 | 0 / 4 | 1 / 2 |

**条目级 12/12 个单元零翻转。** 维度归属会抖（judge-a 在 `ascend/00028` 上给出 4 种不同的失败维度组合，但每次都有 `meaning`），所以**逐维度归因不可复现，条目级判定可复现**。

`cmn/1668` 是稳定分歧：judge-a 四次全过、judge-b 四次全败，不是噪声，是两把尺子不一致。

## 3. 边界 item 一次采样等于掷硬币

6 条 item × 6 个独立译文样本，每样本双评委各判一次（72 次调用）：

| item | 通过样本 | 通过率 | 状态 |
|---|---|---|---|
| cmn/1671 | 3 / 6 | 50.0% | **不稳定** |
| en_us/1673 | 6 / 6 | 100% | 稳定 |
| en_us/1681 | 6 / 6 | 100% | 稳定 |
| ascend/00004 | 0 / 6 | 0% | 稳定 |
| cmn/1679 | 6 / 6 | 100% | 稳定 |
| en_us/1682 | 0 / 6 | 0% | 稳定 |

`cmn/1671` 的 6 个样本是 3 种译文：judge-a 三种全过；judge-b 在其中两种改述上判 `meaning` 失败。也就是说这条**正好压在 judge-b 的判定边界上**，改述一换就翻面，与随机无关。

这解释了 B2 观察到的“两次运行翻转 2 条”：不是评委不稳，是边界 item 的译文抽样。

## 4. 噪声底与样本数

以“36 条中 1/6 处于边界”（本次实测比例，区间很宽）估算，36 条总分的运行间标准误：

| 每个 item 的样本数 | 评委调用 | 判审成本（USD） | 期望 SE（36 条） |
|---|---|---|---|
| 1 | 72 | 0.024 | **3.4 个点** |
| 3 | 216 | 0.072 | 2.0 个点 |
| 5 | 360 | 0.120 | 1.5 个点 |
| 12 | 864 | 0.289 | **1.0 个点** |

成本按本轮实测 `0.00033386 USD/次`计。翻译调用另计 token（仓库内无单价），N=3 时 108 次。

结论：**要谈“提升了 2 个点”，至少 N=3；要谈 1 个点，需要 N≈12。** 单次运行的 3.4 点噪声会吃掉大多数真实改进。

## 5. 协议（已入库，含单测）

`docs/qa/checks/repro-aggregate.js`，纯函数，10 条单测在 `test/qa-repro-aggregate.test.js`：

- 一个样本有效 ⇔ 两个评委都返回完整七维判决
- 样本通过 ⇔ 两个评委七维全过
- item 分数 = 样本通过率，**不是**一次二元判定
- `0 < 通过数 < 样本数` 的 item 标记 `unstable`，必须单列
- 运行分数 = item 通过率的无权平均，附二项模型 SE 与 95% 区间

报告一张榜单时同时给：`score`、`se`、`unstableItems`。没有后两项的单个数字应视为一次抽样，不作为结论。

## 6. 产品侧的含义

- 同一句话、同一设置，用户两次得到不同译文；`seed` 不能用来固定。客户端若要“同一句不重复请求”的缓存，只能按输入哈希缓存**一次抽样**，不能假设服务端会给出相同结果。
- 回包无 `system_fingerprint`，无法在日志里区分“模型换了”与“采样抖了”。
- 计费按实际 token，同一句的 completion token 数会随抽样变化，预算要留余量。

## 7. 复现

```bash
cd docs/qa/experiments/e2e-b2c-noise-20261118
node scripts/probe-seed.js      # 120 calls ~4 min
node scripts/probe-judge.js     # 48 calls  ~1 min
node scripts/probe-samples.js   # 72 calls  ~2 min; reads out/calls/ if present, else out/seed-calls.jsonl
node aggregate.js               # offline, rebuilds out/repro-summary.json
```

脚本从 `~/mobiletranslator/.local/keys.md` 读密钥，只驻留内存。`out/*.jsonl` 是逐次调用记录，`aggregate.js` 只用这些文件重算，不联网。

## 9. 没解决的

- 只有 6 条 item、一个 provider（qwencloud 兼容端点）。边界 item 比例 1/6 的置信区间很宽（0–40%），N 的取值应在 36 条全量跑一次后重算。
- `judge-b` 对 `cmn/1671` 的两种改述判 `meaning` 失败，究竟是“改述损失了命题”还是“尺子过严”，本记录没有裁定。这是仪器问题，不是噪声问题，需要人审那两条。
- 逐维度归因不稳定，本记录不提供维度级置信区间。
- 翻译 token 无单价，无法折算美元。
