把首屏还给实时字幕与听译

这一稿只做一件事：把「登录后的第一屏」从系统翻译的安装说明书，改成两个别处做不到的能力的启动台。下面先解剖现状，再给新版层级，最后是取舍与待你拍板的地方。

可点击原型 · iPhone 可点击原型 · Mac 一页规格 + 判据

结论：①「系统翻译」三步块从首屏移除，改为三引擎就位后才出现的一行状态入口；② 顶栏收编账号行；③ 首屏主体换成实时字幕与实时听译两张等权主卡；④ 复习卡压成一条；⑤ 删除底部红字，缺引擎改由顶部状态行可就地点击修复。

裁定 1
系统翻译撤出首屏，配全后才出现，且做成一行而不是三步块。
裁定 2
登录即三引擎就位，实时字幕与实时听译直接可用，不再有「还没配」提示。
裁定 3
两张实时卡等高、等按钮样式、同色，作为本页唯一的两个实心按钮。
裁定 4
复习降为一条，首屏可见、一眼可开始；详细统计下沉到二级。

红色虚线 = 844pt 折叠线。以上五块之外，这一屏没有任何实时字幕或听译的入口。

1顶部 508pt 讲的是「怎么装」，而用户早就装好了

三步操作说明 + 一枚「我已设好」按钮，占掉首屏 60.2%。这是一段 onboarding 语汇，出现在「登录之后」这个稳态里，就只剩信息噪音。真正的代价不是浪费空间，是它把两个核心入口挤到折叠线以下。

改法　撤出首屏。改成一行「系统翻译 · 已交给『翻译』App」，仅在三引擎就位后出现，点了才展开说明。

2「我已设好」是一枚不推进任何状态的假按钮

点了不改变引擎状态、不改变版面、不给反馈。用户不知道它到底确认了没有，于是反复点。这类按钮会持续消耗首屏最贵的一块版面。

改法　删掉。配置状态改由顶部状态行如实呈现 —— 就位就是就位，缺失就是「可点的缺失」，没有一个需要「我已设好」的主语。

3账号行占一条横带，却只装最低频的两个动作

邮箱 + 设置 / 退出被写成文字链，命中区不足 44pt，却是每屏必看的版面。行高 48pt 换来的信息量约等于一行页脚。

改法　收进顶栏 44×44 的账户按钮，设置 / 退出进二级面板。iPhone 上省下 48pt + 16pt 间距，Mac 上直接落到侧栏底部。

4复习卡占 396pt，把五个等权数字摊开给你看

190 / 190 / 4664 / 4474 / 0 同字号同色，读者不知道该看哪个；进度条在「已掌握 0」时是一条 0% 的空槽，传达的是失败感；「开始复习」落在 y≈1010，必须滚动 166pt 才能完整看到。这违反了裁定 4 的「一眼能开始」。

改法　压成 76pt 一条：只留「今天待复习 190」+ 微型进度 + 淡色「开始复习」；其余四个数字与「同步」进二级页。

5「翻译文档」被塞进「听」分区，破坏分区语义

文档翻译是异步离线任务，和「听这台设备的声音」不是同一件事。放在「听」下面，会让人以为它也是实时能力的一条分支。

改法　独立成「文档」分区、列表行形态，排在折叠线以下。首屏的两个实时能力是「声音」，文档是「文件」，不混。

6红字告警在 y=1275，而且点不动

「还没配语音引擎 —— 到『设置 › 朗读』里选一个」需要滚动 431pt 才能看到；看到了也只能自己走。纯文本告警没有恢复路径，红色还把它渲染成一件严重的事，其实它只是一个待办。

改法　删。缺失态上移到顶部状态行，缺失项自身就是 44pt 命中区，点了直达设置对应页；红色只留给真正的失败（权限被拒、引擎崩溃）。

03

取舍：我考虑过什么，以及为什么这么定

5 个岔路口

系统翻译块去哪：撤出首屏 / 移进设置 / 折叠收进折叠面板

选定 撤出 + 置底一行
为什么
它的信息只在用户确认「已经接管」之后才有价值。所以正确的时机不是「登录后」，而是三引擎就位后 —— 状态是它的开关，不是用户点的那枚按钮。
否掉 B
整段移进设置。代价是用户完全不知道系统「翻译」已经被接管了，而这件事是本产品相对系统 App 的独占优势，值得留在首页一行。留着「知道」的成本只有 56pt 列表行。
否掉 C
折叠成 accordion。收起时问题解决了，但用户一展开就回到今天的版面 —— 而且 accordion 会在首屏制造一个「还有更多」的假承诺。不可取。
形态
一行、带真实系统「翻译」App 图标、文案陈述事实（「已交给『翻译』App」），不再有步骤、不再有按钮。点击才展开说明。
风险　扩展被系统撤销后，这一行会变成失效陈述。规则：行右侧改为「需重新授权 ›」的 terra chip，且不消失（消失会让人以为功能没了）。

两个实时能力：同权双主卡，还是一主一次

选定 同权双主卡
为什么
裁定 3 把两者并列为本页主角。若为了视觉节制把「实时听译」降成描边按钮，等于在版面上宣布它的能力比字幕低一档 —— 而这个产品里，面对面逐句转写＋翻译＋朗读是字幕做不到的闭环。
怎么压噪声
两卡等宽等高、同色同尺寸按钮，靠卡内视觉区分（波形带 vs A·B 译文条）。两个实心按钮在同屏出现，代价是首屏更满 —— 我认为这个代价值得，因为满的两张卡恰好也把复习条抬进了首屏。
否掉的
「卡片 + 整卡可点」方案：更省版面，但两张大卡当按钮，命中区大却语义模糊，VoiceOver 朗读出来是一整块卡片文字。
需要你确认　若你更看重首屏留白，备选是「字幕卡满宽 236 + 听译卡压缩成 120 单行条」。我按裁定 3 的字面意思做了同权版。

引擎状态行：放顶部还是留作页脚告警

选定 顶部一行，三态同高
为什么
它有两种截然不同的身份：就绪时是保证（可以开始了），缺失时是待办（点这里去修）。保证可以低调，待办不能。放在同一条上，缺失项原地变成 44pt 的可点 chip，不用跳页也不用读页脚。
为什么不用红色
缺一个语音引擎是待办不是故障，用 terra 标注；#b3261e 只留给真正的失败（权限被拒、引擎崩溃、文件解析失败）。这条同时消掉了现状第 6 条的红色滥用。
稳定高度
就位 / 部分缺失 / 全缺三种态都是 32pt 高、同一位置 —— 引擎变化不会让下面两张主卡跳动，实时字幕不会因为朗读引擎被换掉而位移。
风险　三段名字 + 状态在 320pt 宽机型（如 SE）会挤。规则：最左标签「引擎」在 ≤359pt 隐藏，缺失项优先显示，摘要后置。

复习卡：压成一条，还是换个位置

选定 首屏第三条
为什么
裁定 4 要它「仍看得见、一眼能开始」，所以不能沉底。76pt 是能同时满足「可点」和「不抢戏」的最小值：1 个数字（190）+ 1 条 11.5pt 的「查看统计 ›」文字入口 + 1 枚 40pt 淡色按钮。
丢掉什么
190/190/4664/4474/0 里的另外四个数字，以及「同步」。它们进二级页，由这条左下角的文字入口进入。0 不再作为主视觉 —— 0% 的空进度条传达失败感；「已过 7 天」这类进度量需要真实统计口径支撑，本稿没有该数据，不做占位数字，只留入口。
否掉的
「复习」做成 Tab：单词是独立的学习行为，塞进首页的实时工作流里本来就别扭，Tab 是更彻底的解，但它超出现在这一屏的范围里。
注意　「已掌握 0」在详情页必须保留原样呈现（这是真数据）；被去掉的只是它在首页的主视觉位置。

「翻译文档」：留在「听」分区 / 移出 / 删

选定 独立「文档」分区
为什么
「听」如果继续做分区，就该只装与声音实时有关的东西。文档是异步、离线、可离线的文件任务，混放会让用户对「听」的能力边界产生错误预期 —— 这正是你裁定 3 想守住的东西。
排序
文档与系统翻译都排在折叠线以下。低频不是问题，「低频却挤在首屏」才是问题。
否掉的
直接删掉。它是真实在用的功能（PDF/Word/图片），删掉等于让用户找不到，损失大于它在版面上占的 96pt。
04

评审时需要你拍板的四件事

这四条会影响写进交互规约的措辞

1　「系统翻译」的触发条件，按哪个？

我按三引擎全就位实现（一出现就说明整套东西都能用了）。备选是「三引擎就位 且 浏览器扩展已授权」—— 更贴合「交给『翻译』App」这句话的语义，但登录后短期内大概率不成立，那一行就长期不出现。裁定 1 写的是「等用户把引擎完整配好之后」，我按字面取「引擎」。

倾向：三引擎就位即出现。确认？

2　「已掌握 0」在首页真的一个字都不留吗？

我把首页的展示数字压到 1 个（190），0 完全进二级页。若你希望用户看到启动进度（毕竟 4474 候选 / 0 掌握是很早期的状态），我可以在复习条里加一行 4pt 高的文字「已掌握 0 / 候选 4474」，不占视觉重心。这与判据「首屏展示数字 ≤ 2」不冲突。

倾向：留白，把 0 放二级。你要哪一版？

3　实时字幕要不要在首页就暴露「字幕浮窗 / 锁屏」？

我做的是：开始后在卡内出双语字幕 + 计时，浮窗开关放在进行中态里，不进默认态。理由是默认态只留启动决策。但如果实时字幕的主要用法是「开着浮窗锁屏看」，那它值得占一个首页位置 —— 这会改变 H1 卡的高度预算。

倾向：留在进行中态。你确认？

4　Mac 版是同一套卡片的宽屏，还是改成侧栏 + 双栏工作台？

我按 macOS 原生范式做：侧栏 232pt 收纳目的地（实时字幕 / 实时听译 / 单词卡 / 文档 / 系统翻译），主区只放两张主卡 + 复习条；系统翻译在 Mac 上落在侧栏而不是主区列表行 —— 那是宽屏版对「轻」最省事的落地。若你要求两版结构完全对称，我改成主区同 iPhone 顺序。

倾向：Mac 走侧栏。你确认？
